# 第 3 阶段：实时预览

## 1. 目标

在网页中直接查看已经配置并启用的视频通道实时画面。

## 2. 页面功能

- 展示所有已启用的视频通道。
- 支持单画面、4 宫格和 9 宫格布局。
- 通道数量超过当前布局容量时显示上一页、下一页和页码按钮。
- 宫格画面可快捷切换到单画面。
- 显示通道名称、视频源类型、连接状态、预览分辨率和预览 FPS。
- 断流时显示错误信息并自动重连。
- cameraIndexCode 重连时重新调用接口获取有效 RTSP 地址。

## 3. 实现方案

- 浏览器使用 MJPEG 接收实时画面。
- 后端每个正在显示的通道只建立一个共享取流会话。
- 同一路通道的多个网页观看者共享最新 JPEG 帧，避免重复连接 RTSP。
- 切页或离开页面后，无观看者的取流会话在空闲期后自动释放。
- RTSP 使用 TCP 传输。
- 预览最大宽度为 1280，目标输出上限为 10 FPS，降低多宫格时的 CPU 和网络开销。

## 4. 已确认需求

| 问题 | 答案 |
|---|---|
| 预览数据来源 | 已配置并启用的视频通道 |
| 支持布局 | 单画面、4 宫格、9 宫格 |
| 默认布局 | 4 宫格 |
| 超出宫格容量 | 显示上一页、下一页和页码按钮 |
| cameraIndexCode 断流处理 | 重新解析 RTSP 并自动重连 |

## 5. 验收标准

- [x] 能从视频通道页面进入实时预览页面。
- [x] 能显示 cameraIndexCode 通道实时画面。
- [x] 支持单画面、4 宫格和 9 宫格切换。
- [x] 超过当前布局容量时能够翻页和选择页码。
- [x] 显示通道名称、状态、分辨率和 FPS。
- [x] 同一路通道的多个观看者复用一个后端取流会话。
- [x] 断流时进入重连状态，cameraIndexCode 会重新解析地址。
- [x] 离开页面后能够释放无人观看的取流会话。

## 6. 本阶段不做

- 不叠加模型检测框。
- 不进行历史录像检索。
- 不控制摄像机云台。
- 不使用 WebRTC。
- 不启动视频检测任务或生成告警。
